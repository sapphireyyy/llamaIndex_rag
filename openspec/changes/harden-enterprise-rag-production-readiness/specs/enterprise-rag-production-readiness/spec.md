## Purpose

定义企业 RAG 平台可被认定为生产就绪时必须满足的运行时契约，覆盖真实异步入库、数据库级租户隔离、可信流式响应、版本化处理策略和权威事实源一致性，并为故障、重试、取消与发布验收提供可重复验证的行为标准。

## ADDED Requirements

### Requirement: 上传提交与入库处理必须真正解耦
系统 MUST 在返回 `202 Accepted` 前持久化入库任务及其可可靠恢复的处理意图，并 MUST 在 API 请求边界之外执行解析、切分、Embedding、索引暂存和发布。API 进程在响应后退出不得导致已接受任务丢失。

#### Scenario: 接受有效上传
- **WHEN** 获得授权的用户提交符合租户上传策略的文件
- **THEN** 系统返回 `202 Accepted`、稳定的任务标识和初始排队状态
- **AND** 响应不等待文档解析、Embedding 或索引发布完成

#### Scenario: 响应后 API 进程退出
- **WHEN** API 已返回 `202 Accepted` 且随后在后台处理开始前退出
- **THEN** 后台 Worker 仍能发现并完成该任务，或把它推进到可诊断的终态

#### Scenario: 无法持久化处理意图
- **WHEN** 系统无法原子地保存任务及其可靠处理意图
- **THEN** 系统不得返回 `202 Accepted`
- **AND** 不得留下永远无法被后台处理的可见排队任务

#### Scenario: 重复提交相同幂等请求
- **WHEN** 客户端以相同幂等键和相同请求内容重复上传
- **THEN** 系统返回同一逻辑任务或其既有结果
- **AND** 后台最多产生一次可见的活动文档版本发布效果

### Requirement: 后台入库必须具备至少一次投递下的单次业务效果
后台 Worker MUST 驱动排队任务的状态迁移，并在消息重复、Worker 重启、超时重试或部分依赖失败时保持幂等。新版本只有在所有必需索引验证通过后才能成为活动版本，失败或取消 MUST 保留最后一个有效活动版本。

#### Scenario: Worker 完成排队任务
- **WHEN** Worker 领取一个排队任务且所有处理阶段成功
- **THEN** 任务依次产生可追溯的阶段状态并最终标记为成功
- **AND** 新文档版本及其检索投影以一个逻辑发布动作变为活动状态

#### Scenario: 同一任务被重复投递
- **WHEN** 相同任务消息被一个或多个 Worker 重复领取
- **THEN** 系统不得生成重复的活动 Chunk、重复发布索引或重复消费持久配额
- **AND** 所有投递最终收敛到同一任务结果

#### Scenario: Worker 在处理中重启
- **WHEN** Worker 在任务完成前退出且任务租约或可见性超时
- **THEN** 另一个 Worker 能够安全恢复任务
- **AND** 已完成阶段不得造成不可逆的重复副作用

#### Scenario: 发布前收到取消
- **WHEN** 已接受任务在新版本发布前被授权用户取消
- **THEN** Worker 停止后续可中断阶段并把任务标记为已取消
- **AND** 系统不得切换活动版本

#### Scenario: 新索引发布失败
- **WHEN** 任一必需检索投影无法验证或发布
- **THEN** 任务进入可重试或失败终态并记录可诊断原因
- **AND** 旧活动版本继续提供服务，新投影不得被视为已发布

### Requirement: 生产数据库角色必须强制执行租户 RLS
生产部署 MUST 分离数据库迁移身份与应用运行身份。应用运行身份 MUST 不是超级用户、不得拥有 `BYPASSRLS`、不得拥有受保护业务表，并 MUST 在真实 PostgreSQL 上以该身份通过 RLS 读写隔离验收；仅有应用层过滤或特权账号测试不得作为生产隔离证据。

#### Scenario: 跨租户读取
- **WHEN** 应用运行身份在租户 A 的事务上下文中查询同时包含租户 A 和租户 B 数据的受保护表
- **THEN** 数据库只返回租户 A 的记录
- **AND** 按租户 B 标识直接读取的结果表现为不存在或被拒绝

#### Scenario: 跨租户写入
- **WHEN** 应用运行身份在租户 A 的事务上下文中尝试插入、更新或删除租户 B 的记录
- **THEN** 数据库拒绝该写入且不产生部分变更

#### Scenario: 缺少租户事务上下文
- **WHEN** 应用运行身份访问受 RLS 保护的数据但事务未绑定有效租户
- **THEN** 数据库默认拒绝读取和写入租户数据

#### Scenario: 运行账号具有绕过能力
- **WHEN** 生产就绪检查发现应用账号为超级用户、拥有 `BYPASSRLS` 或拥有受保护业务表
- **THEN** 部署不得进入就绪状态或通过发布门禁
- **AND** 检查结果明确指出不合规的数据库属性

### Requirement: 回答交付模式必须真实反映 Provider 能力
模型 Provider MUST 显式声明是否能够增量生成。支持增量生成时，系统 MUST 在上游生成完成前传递真实增量；不支持时，系统 MUST 将交付模式标记为 `buffered`，并不得把完整答案按词切片伪装成真实流。每次查询无论采用何种交付模式都 MUST 只有一个明确终态。

#### Scenario: Provider 提供真实增量
- **WHEN** 已选 Provider 声明支持增量生成并逐步产生答案内容
- **THEN** 客户端在上游生成结束前收到顺序一致的答案增量
- **AND** 查询元数据将交付模式标记为 `streaming`

#### Scenario: Provider 不支持增量生成
- **WHEN** 已选 Provider 只支持完整回答
- **THEN** 客户端收到标记为 `buffered` 的回答交付
- **AND** 系统不得制造声称来自上游 Token 流的延迟分片

#### Scenario: 客户端取消流式查询
- **WHEN** 客户端在增量生成期间取消查询
- **THEN** 系统停止继续读取或转发 Provider 输出并释放相关资源
- **AND** 查询最终状态为 `cancelled`，此后不再发出成功终态

#### Scenario: 部分输出后发生错误
- **WHEN** 系统已发送部分答案增量后 Provider、连接或输出校验失败
- **THEN** 系统发出唯一的失败或降级终态及可关联错误信息
- **AND** 不得把未通过最终校验的部分内容记录为成功答案

### Requirement: 生产环境必须显式配置生成式模型
生产模式 MUST 显式选择可用的生成式模型 Provider，并在就绪前验证 Provider Profile、Secret Binding、网络策略和所需能力。`extractive` MUST 仅用于开发、测试或被策略明确允许的降级路径，并 MUST NOT 作为生产环境的隐式默认模型。

#### Scenario: 生产环境只存在隐式 extractive 默认值
- **WHEN** 生产部署未显式配置并激活生成式模型 Provider
- **THEN** 模型能力检查失败且查询服务不得被报告为生产就绪

#### Scenario: 生产 Provider 配置有效
- **WHEN** 生产部署引用租户允许的生成式 Provider、有效 Secret Binding 和兼容能力
- **THEN** 就绪检查通过模型配置项
- **AND** 查询执行记录保存实际 Provider Profile、模型和能力快照

#### Scenario: 显式允许模型降级
- **WHEN** 主 Provider 不可用且活动策略明确允许指定回退 Provider
- **THEN** 系统只使用该已验证回退并把回答标记为降级
- **AND** 审计与用量记录同时保留主 Provider 失败和实际回退信息

#### Scenario: 开发环境使用 extractive
- **WHEN** 非生产环境显式选择本地 `extractive` Provider
- **THEN** 系统允许确定性回答用于开发或测试
- **AND** 其交付能力不得被误报为真实上游增量生成

### Requirement: 文档切分策略必须按租户版本化并随任务快照
租户配置 MUST 提供有边界校验的 `chunk_size` 与 `chunk_overlap`，其中重叠量必须小于块大小。每个入库任务 MUST 固定其提交时生效的配置版本和有效切分参数；任务运行期间的配置切换不得改变该任务结果的解释语义。

#### Scenario: 使用租户切分配置提交任务
- **WHEN** 租户在活动配置中设置合法的切分参数并提交文档
- **THEN** 任务记录保存配置版本及有效参数
- **AND** 所有 Chunk 可追溯到该处理配置

#### Scenario: 切分参数无效
- **WHEN** 管理员提交超出允许范围或 `chunk_overlap >= chunk_size` 的租户配置
- **THEN** 系统拒绝激活该配置并返回字段级校验原因

#### Scenario: 任务执行期间配置切换
- **WHEN** 已排队任务尚未完成时租户激活新的切分配置
- **THEN** 既有任务继续使用提交时快照
- **AND** 新提交任务使用新配置版本

#### Scenario: 对既有文档应用新切分配置
- **WHEN** 管理员激活新切分配置后请求重建既有文档索引
- **THEN** 系统创建可追溯的新处理代次并完成暂存验证后原子发布
- **AND** 发布前旧代次保持活动，配置激活本身不得就地改写既有 Chunk

### Requirement: OCR 必须受租户策略约束并保留来源证据
系统 MUST 支持租户将 OCR 配置为 `disabled`、`best_effort` 或 `required`，并仅对符合策略的扫描型或无足够可提取文本的内容执行 OCR。OCR 结果 MUST 保存页码或区域、置信度、Provider、处理版本和原始文件引用，外部 OCR MUST 同时满足外联、Secret、配额和内容捕获策略。

#### Scenario: 扫描型 PDF 启用 OCR
- **WHEN** 文档页面没有足够的原生可提取文本且租户 OCR 策略允许所选 Provider
- **THEN** 系统把 OCR 文本作为带页码、区域和置信度的解析单元参与后续处理
- **AND** 引用仍能定位到原始文档页面而不是仅定位到 OCR 文本

#### Scenario: 外部 OCR 被租户策略禁止
- **WHEN** OCR Provider 需要外部网络或 Secret，但租户策略未授权对应能力
- **THEN** 系统不得发送文档内容到该 Provider
- **AND** 按 `best_effort` 或 `required` 模式产生明确的跳过或失败结果

#### Scenario: best-effort OCR 失败
- **WHEN** OCR 模式为 `best_effort` 且部分页面识别失败
- **THEN** 系统保留可用的原生文本与成功 OCR 结果并记录降级诊断
- **AND** 失败页面不得生成看似成功但无来源的文本

#### Scenario: required OCR 失败
- **WHEN** OCR 模式为 `required` 且必需页面无法完成识别
- **THEN** 入库任务失败且不得发布不完整的新版本
- **AND** 最后有效活动版本保持不变

### Requirement: 查询必须执行完整且不可变的检索策略快照
每次查询 MUST 从已激活助手版本解析一个完整、租户归属有效的检索策略快照，覆盖双路召回、融合、重排、证据数量、相关性阈值、上下文预算和允许的降级行为。缺省值必须来自可识别的版本化策略，运行时代码默认值不得静默覆盖或补齐未追踪参数。

#### Scenario: 执行自定义检索策略
- **WHEN** 活动助手版本引用包含自定义召回、融合、重排和证据参数的有效策略
- **THEN** 查询所有检索阶段使用该策略的有效值
- **AND** 查询记录保存策略标识、版本、哈希和最终参数

#### Scenario: 策略使用版本化默认值
- **WHEN** 助手未覆盖某项可选检索参数
- **THEN** 系统从其引用的版本化默认策略解析该值
- **AND** 解析来源在查询快照中可追溯

#### Scenario: 查询期间激活新策略
- **WHEN** 查询开始后管理员激活新的检索策略版本
- **THEN** 进行中的查询继续使用开始时快照
- **AND** 后续查询使用新版本

#### Scenario: 策略缺失、失效或跨租户
- **WHEN** 助手引用的检索策略无法解析、未激活或不属于当前租户
- **THEN** 系统在执行任何搜索前拒绝查询
- **AND** 不得回退到未版本化的代码默认值

### Requirement: PostgreSQL 必须保持授权与发布状态的事实源
系统 MUST 以 PostgreSQL 中的租户、成员关系、ACL epoch、文档状态、活动文档版本、配置版本和策略版本作为权威事实。向量与词法索引只可作为可重建的检索投影；候选进入模型上下文及引用源被访问前 MUST 依据当前权威状态重新验证。

#### Scenario: 外部索引包含陈旧的已撤权候选
- **WHEN** 检索投影返回的候选在 PostgreSQL 中已失去访问权限、已失效或不再属于活动版本
- **THEN** 系统在模型上下文组装前排除该候选
- **AND** 记录可观察的陈旧投影信号以触发修复或重建

#### Scenario: PostgreSQL 权威状态不可用
- **WHEN** 查询无法取得所需租户、授权或活动版本事实
- **THEN** 系统默认拒绝使用外部索引结果
- **AND** 不得仅凭向量或词法索引缓存继续回答

#### Scenario: 从权威数据重建检索投影
- **WHEN** 外部索引丢失、损坏或被判定为陈旧
- **THEN** 授权操作员能够从 PostgreSQL 状态与受管原始内容重建投影
- **AND** 新投影通过租户、ACL、版本和数量校验后才可发布

#### Scenario: 引用在回答后失效
- **WHEN** 用户访问引用源时对应权限已撤销、文档已删除或活动版本已切换
- **THEN** 系统依据当前 PostgreSQL 状态拒绝源访问
- **AND** 不因索引中仍存在旧 Chunk 而泄露内容
